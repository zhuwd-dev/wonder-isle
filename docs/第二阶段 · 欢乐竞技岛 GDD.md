# 《奇趣小岛》第二阶段 GDD：欢乐竞技岛

版本：V2.0—V2.8 产品基线
状态：方向与版本边界已由产品确认；未标注“已确认”的关卡参数均为设计建议，需通过试玩调整。
目标年龄：6–8 岁
依赖：第一阶段《奇趣小岛》V1.0 GDD 与既有 Q001–Q012 存档

## 1. 阶段定位

第二阶段在生活小岛的探索、助人、收集、建造体验之外，加入一处可反复游玩的低压力竞速游乐区。核心乐趣是“发现入口、选择玩法、沿清楚的路线跑一趟、得到积极反馈、回到自己的小岛”。竞技强调移动、观察路线和轻松尝试，不强调惩罚、淘汰、付费竞争或速度焦虑。

生活小岛仍是玩家的熟悉基地：第一阶段任务、装饰、伙伴关系和存档语义保持不变。竞技岛是独立区域，V2.0 只开放入口、大厅和 R01 基础体验；竞赛计时、AI 对抗、奖励经济、联机均按后续版本逐步开放。竞技岛状态不得重置或重复发放第一阶段任务奖励。

阶段目标：

- 建立从生活小岛到竞技岛、再返回的清楚闭环。
- 让儿童无需阅读长篇说明即可认出单人挑战与未开放玩法。
- 先验证可复用的赛道、检查点、终点和场景切换架构。
- 所有失败都可快速恢复；不因碰撞、走错路或退出而损失生活小岛进度。

## 2. 世界与地图结构

### 2.1 生活小岛入口

入口应成为世界内可见的木质码头或彩虹小桥，而非悬浮菜单按钮。与生活小岛河岸、已有桥梁和装饰视觉统一，具备接地阴影、前后遮挡、独立碰撞和靠近高亮。入口由 Q001 修桥完成解锁；未完成时表现为友善的未开放状态，并以图形提示“先修好小桥”。建议把入口放在玩家完成 Q001 后可自然抵达的河岸边，确切坐标待地图碰撞试玩确认。

靠近入口后显示简短动作提示“去竞技岛玩”，右下角沿用通用互动按钮。交互触发轻量淡入/渡船或彩虹闪光转场，不在切换时重建主角或重新播放第一阶段开场。

### 2.2 竞技大厅

竞技大厅是一张独立可探索的小型场景，不是后台菜单。空间包含中央迎宾广场、R01 单人赛道入口、动物伙伴报名牌、好友入口、奖杯展示台、回生活小岛出口及未来玩法预留地块。场景以草地、花朵、木牌、彩旗、蘑菇和柔和水岸组成；可见动线从入口通往三个大入口。建议单屏即可读懂主入口，必要时支持镜头平移。

三个入口：

| 入口 | V2.0 状态 | 反馈 |
|---|---|---|
| 单人挑战 | 开放 | 进入 R01「彩虹草地赛」基础体验 |
| 动物 AI 大赛 | 未开放 | 展示兔子、狐狸、乌龟，提示“动物伙伴正在准备比赛” |
| 好友一起玩 | 未开放 | 提示“好友竞技即将开放” |

未开放入口仍是明确的预告展示，不伪装成可玩的 AI 或联网房间。返回生活小岛的出口始终可见、可交互。

### 2.3 六条赛道主题

赛道难度按“认识方向—单一动作—组合动作—路线规划—综合练习”递进。下表中的障碍数量、长度、计时值和坐标均为**待试玩调整的建议**，不是已批准的固定数值。

| 赛道 | 主题与视觉 | 核心机制与障碍 | 建议难度 / 版本 |
|---|---|---|---|
| R01 彩虹草地赛 | 阳光草坡、花朵路标、彩虹终点 | 基础路线转弯、绕木桩、宽赛道；V2.0 先做无计时体验，V2.1 加跳跃、检查点和计时 | 入门 / V2.0 基础、V2.1 正式 |
| R02 蘑菇弹跳林 | 蘑菇林、苔藓地、林间木桥 | 弹跳蘑菇、落点平台、短桥连接 | 初阶动作 / V2.3 |
| R03 摇摇木桥 | 溪谷木桥、绳索和浅水 | 摇摆桥面、节奏踏板、掉落后回最近检查点 | 平衡与时机 / V2.3 |
| R04 溪流跳跳乐 | 清澈溪流、石头和水车 | 踏石、短距离跳跃、流向提示 | 连续动作 / V2.5 |
| R05 风车花园赛 | 风车、花田、篱笆小径 | 风向区域、转动风车门、分岔捷径 | 路线选择 / V2.5 |
| R06 欢乐冠军赛 | 嘉年华广场与综合布景 | 从 R01–R05 选取温和组合挑战；可重试，不采用淘汰赛 | 综合复习 / V2.6 |

正式布局以可读性优先：赛道边缘通过自然地形、围栏、浅水或柔和边界表达，避免看不见的硬墙；路标颜色、形状和动画共同指向前进方向。所有障碍预留绕行或宽容判定。

## 3. 模式与比赛规则

### 3.1 单人挑战

V2.0 开放 R01 的起点到终点基础路线。第一次体验包含起跑提示、清晰路标、一个可绕行木桩障碍和终点反馈，目标时长建议为 30–60 秒，待试玩校正。V2.0 不记录正式竞速成绩、不发奖牌或竞技星星。V2.1 再加入正式计时、检查点与跳跃。

### 3.2 动物 AI 大赛

V2.2 才开放兔子、狐狸、乌龟作为可识别的 AI 对手。AI 采用可预测、儿童友好的赛道跟随和有限变速；不阻挡玩家、不作弊瞬移、不因输赢扣除资源。难度应以路线选择和节奏差异体现，并支持单独练习。具体 AI 数量、配速和追赶逻辑待试玩确定。

### 3.3 好友联机与合作

V2.7 开放 2–4 人邀请式好友房间与同步比赛；V2.8 增加合作目标。默认不提供陌生人匹配、公开聊天、用户搜索或儿童个人资料展示。房间加入必须由监护人可理解的邀请流程控制，提供退出和举报/屏蔽所需的适龄产品保护。网络协议、权威端、断线恢复、平台合规和家长控制在联机版本单独评审，不在 V2.0 预埋复杂网络框架。

合作竞技侧重共同完成路线目标，例如一起触发机关、收集赛道上的可视标记或协力抵达终点；不得把队友失误变成资源损失或进度惩罚。

## 4. 操作、碰撞与恢复

- 桌面沿用 WASD/方向键、现有鼠标交互和通用互动按钮；手机沿用虚拟摇杆，互动按钮位于右下拇指区域。
- 主角复用第一阶段移动、四方向 Idle/Walk、脚底锚点、碰撞与绘制逻辑。斜向输入归一化，四方向朝向沿用已有规则。
- V2.0 不要求跳跃；V2.1 引入单一、易触达的跳跃操作，落地碰撞以角色脚底/地面高度为准，避免仅用整图位移假装腾空。
- 障碍碰撞优先使用宽容边界；轻碰只造成短暂减速或回到当前检查点，不死亡、不重置整场、不损失物品。
- 检查点存储当前赛道与最近安全位置。退出赛道、刷新页面或主动返回时先询问/提供清楚选择；重新进入时恢复到安全起点或已保存检查点。
- 错误方向以路标、可见路线和软边界纠正，禁止无限卡住。终点触发区域必须宽，停留或互动均可完成。

精确速度、碰撞半径、跳跃时长、检查点数量和计时宽限值均属于待试玩参数，应在真实设备观察后调整。

## 5. 成长、奖励与存档

V2.0 只保留竞技岛解锁（可由 Q001 完成状态推导）及 R01 初次体验完成标记（若确有后续引导需求）。不新增重复的解锁字段，不改变 Q001–Q012 状态定义。无正式竞技奖励。

V2.4 才引入竞技奖牌、星星、成绩记录和奖励。奖励应按体验参与与个人进步发放，不以速度排名压迫低龄玩家；不设计付费道具、随机奖励箱或限时奖励。成绩只保存本地匿名的赛道 ID、个人最佳或完成状态，不保存姓名、头像、好友名单或其他儿童个人信息。具体奖励数量和保存字段待经济与隐私评审。

旧存档读取必须兼容：新增字段设默认值；第一阶段存档迁移不得重写或清空用户任务、装饰、植物和伙伴状态。竞技存档与生活岛进度分域或以向后兼容字段隔离。测试必须使用隔离存档路径。

## 6. 美术、音频、UI 与适配

### 6.1 视觉方向

延续第一阶段柔和童话自然风格、手绘质感、暖色木作、清透水面与花园色彩。竞技元素以彩旗、彩虹弧、花朵路标和木牌表现。角色比例、地面锚点、阴影方向、遮挡层级与现有小老鼠一致。新资源需检查透明边缘、锚点、缩放和色彩协调；灰盒只可用于开发验证，不能列为正式视觉验收。

### 6.2 UI 与动画

每屏突出一个主要动作；按钮触控目标建议不小于 56×56 设计像素（待设备测试调整）。文字短句配图标。HUD 不遮挡路线，互动提示始终靠近拇指区域。场景过渡采用短淡入/景物遮挡，不长时间黑屏。终点庆祝以 1–2 秒轻量星光/彩纸、角色欢呼和“太棒了！到达终点！”呈现；提供“再玩一次”和“返回大厅”。不生成正式排名或奖牌 UI 直到相应版本。

### 6.3 音效与动态环境

可使用轻柔起跑铃、木牌提示、到达终点的短庆祝音；所有声音可关闭，默认音量适中。动态环境沿用现有水面、云影、叶片等性能档位和重绘优化，竞技区不新增高频全屏粒子。无音频素材时先用现有资源或静音，不把临时合成音效标记为最终音频。

### 6.4 平台适配

继承 1280×720 设计画布、等比缩放与扩展视野的横屏策略、Web 全屏入口和 PWA 子路径配置。验证桌面 1280×720、1630×870、手机横屏 844×390、竖屏旋转提示、浏览器全屏和 PWA。真实 Android/iOS 设备测试单独标记，不能以模拟替代。

## 8. 技术架构

- 生活岛 Q001–Q012 保持既有实现与存档语义，竞技逻辑不得散落进任务条件分支。
- 场景边界建议为 `life_island`、`competition_hub`、`race` 三类；共享玩家控制器、动画和输入映射，不复制角色系统。
- 竞技会话持有当前模式、赛道 ID、检查点、完成状态和返回目的地；场景切换由单一导航/会话服务执行，避免重复实例与幽灵 UI。
- 赛道定义可配置起点、终点、边界、障碍、检查点和路标；V2.0 只配置 R01 所需数据，不提前抽象网络或复杂竞赛系统。
- 交互对象遵循现有输入和儿童引导规则；场景 UI 有单一生命周期，离开场景即释放。
- 动态地图资源复用现有纹理和性能开关。新增大背景需控制尺寸、压缩和透明覆盖，监控 WebGL2、刷新及低端设备帧时间。

## 9. 测试策略与验收

每版至少运行 Godot 隔离测试、生活岛 Q001–Q012 回归、赛道状态测试、存档升级/恢复、鼠标与触屏输入、WebGL2 加载、连续刷新、横屏多视口和 `git diff --check`。V2.0 专测入口解锁门槛、三种模式状态、Hub/R01 双向切换、起点至终点、庆祝、重玩、返回生活岛时 Q 任务/装饰/存档不变。

视觉验收必须由真实运行截图或录屏佐证；生成图本身不算运行证据。没有设备时标注“模拟验证”，Windows 硬件 GPU、Android/iOS 真机和儿童试玩结果不得推断为通过。

## 10. 儿童安全与体验原则

- 竞技岛离线单人体验无广告、内购、随机付费或时间限制。
- 不出现死亡、羞辱式失败、倒计时恐吓、连败惩罚或强制排名。
- 比赛结果用鼓励参与和个人进步的反馈，不比较现实身份。
- 联机版本默认好友邀请，不提供陌生人匹配或自由文本聊天；上线前单独做监护人同意、数据最小化、隐私与平台政策审查。
- 所有按钮可取消/返回；误触不会消耗物品或重置第一阶段进度。

## 11. V2.0 范围锁定

V2.0 的完成标准是生活岛入口 → 竞技大厅 → R01 起点、路线、宽容障碍 → 终点庆祝 → 重玩或回大厅 → 回生活岛的本地可玩闭环。未开放的 AI 与好友模式只展示预告。计时、奖牌、正式成绩、AI、联网、合作及 R02–R06 均属于后续版本。赛道细节参数须通过实际试玩调整；若缺少高质量场景素材，可以完成可玩灰盒验证并明确标记视觉阻塞，但不得宣称正式美术完成。
