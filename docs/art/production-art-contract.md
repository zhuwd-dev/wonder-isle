# 正式角色、植物和道具接入规范

当前资源已接入一张幼苗 PNG 与一把浇水壶 PNG；这不代表四方向角色动画或植物完整成长组已完成。`assets/art/production-art.json` 为可选资源清单，未制作的状态默认 `enabled: false`。缺件继续使用现有稳定表现；不要把缺件启用。

## 主角

当前移动速度为每秒 260 世界单位。碰撞和排序仍以 `player_position + (0,36)` 的脚底及现有建筑深度规则为准。动画独立于任务和存档，不改变玩家位置。

| 项目 | 合同 |
| --- | --- |
| 命名 | `assets/art/characters/mouse/{idle,walk}_{down,up,left,right}/00.png` 等 |
| 帧数 | 每方向 idle 1 帧，walk 6 帧，共 28 张 |
| 画布 | 每帧 256×256 RGBA PNG，不裁切画布 |
| 可见身体高度 | 208～224 像素，包含耳朵和脚，所有帧保持同一比例 |
| 脚底基准 | (128,232)，承重脚贴基准；摆动脚可以抬起，不能移动整张画布 |
| 安全边缘 | 四边至少 4 像素透明，不能裁掉耳朵、尾巴、围巾或挎包 |
| 游戏显示 | 0.30 倍画布，脚底精确对齐原碰撞锚点 |
| 播放 | walk 10 FPS 循环，按实际位移速度调节；idle 单帧 |
| 切换 | 实际无位移切 idle；方向改变从新序列开始；斜向在轴差不足 0.12 时保留前一方向轴 |
| 镜像 | 默认不镜像。左右各交付 6+1 帧，保留不对称挎包；正背面禁止用侧面镜像替代 |
| 导入 | Godot Texture2D，lossless，关闭 repeat，CanvasItem 使用线性过滤；透明边缘无杂色，不预先叠加阴影 |

角色须保留当前老鼠的耳朵、脸型、服装、围巾、挎包及身体比例。动画控制器使用 `SpriteFrames`，空资源只有八个动画名称，没有占位图片。绘制锚点、稳定阴影和碰撞独立；缺正式素材时不再旋转整张立绘模拟步行。

## 植物

清单为每个状态列出路径、画布、根部锚点、显示缩放。标准画布 128×128，根部 (64,116)，游戏缩放 0.40。根部须自然融入既有花圃，不附带土球、裸根、大块阴影或光晕。

- Q002 已种植：`plants/seedling.png`。未种植不显示植株。
- Q005 未浇水：seedling；浇水后的原有短暂生长过渡：growing；浇水后未采摘：flowering；已采摘：harvested，仍保留活植株。
- 当前幼苗 PNG 使用 128×128 画布、(64,116) 根部锚点、0.40 倍缩放；浇水壶为 `assets/art/props/watering-can.png`，由场景资源注册表加载。growing / flowering / harvested 尚无正式 PNG，继续走现有状态表现。
- Q010 外观奖励：`flowering-unlocked.png`、`harvested-unlocked.png`。不增加成长玩法或存档字段。奖励素材缺失时沿用原外观绘制。
- 生长只改变显示尺寸，根部锚点固定。最终需人工检查叶片、根土接缝和光照。

## Q007～Q011 道具

路径与尺寸以清单为准：shell / shell-reward；path-stone；branch / feather / rope；seed-red / seed-blue / seed-gold；tidy-crate / tidy-bundle / tidy-basket。它们分别映射原贝壳状态、石板、三种鸟屋材料、三种收藏种子、三件整理物品。统一使用 PNG、自然地面锚点与原任务交互范围。不得将已有合格桥梁、石头、种子袋和装饰素材重复制作。

道具在地面、拖拽和托盘共用资源配置。拖起仅改变现有抬起偏移。开启一个资源不会改变物品编号、奖励、任务条件或存档。默认使用已有地面绘制；正式 PNG 应自带必要的柔和接触阴影，不附文字标签或矩形框。

## 检查和接入步骤

1. 按清单放入正式 PNG，先保持 disabled；执行 Godot 编辑器导入。
2. 使用 `godot --headless --path . --script tools/check_art_assets.gd` 检查。报告缺件 `ASSET_REQUIRED`；已存在文件的格式、有效 alpha、画布、可见区域和边缘错误会失败。
3. `-- --strict` 要求清单全部齐全，当前必然失败，这是缺素材报告，不是运行回归通过。
4. 主角 28 帧全部合格后设置 mouse.enabled=true，再运行检查工具加 `-- --build-mouse`。它生成 `mouse-frames.tres` 的真实纹理引用。失败不会覆盖资源。提交 JSON、PNG、`.import` 和 `.tres`。
5. 植物或道具合格后逐项设置 enabled=true，运行检查和游戏回归。Web 导出包含清单；全部 PNG 是 Godot 导入资源。
6. 运行 `tools/run_isolated_tests.py` 和 `tools/test_web_preview.sh`，检查多方向、停止、桥梁、存档和真实截图。资源回归使用内存中的合成测试数据验证控制器，不生成生产占位帧。

自动检查不能证明角色身份一致、动作自然或没有多余肢体；这些仍需美术和实际运行验收。不得据自动检查通过宣布美术完成。
