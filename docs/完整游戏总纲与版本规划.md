# 《奇趣小岛》完整游戏总纲与版本规划

> 规划稿 V0.1｜2026-10-22｜用于确定游戏全貌、版本边界和后续逐版本开发，不代表所有候选玩法已获确认。
>
> **标记说明**：**【已定方向】**来自现有 GDD、既有路线图及历史讨论；**【已实现/待核验】**根据近期 Codex 开发报告，仍以项目代码与验收为准；**【新增建议】**为补足长期游戏体验而提出，实施前需单独确认。

## 01. 游戏介绍

**名称**：《奇趣小岛》（暂用名）  
**类型**：2D 卡通、单人、轻探索、动物伙伴、轻任务、收集与建造装饰。  
**受众**：中国大陆 6—8 岁儿童；家长是下载与设备管理的重要参与者。  
**平台**：优先验证 Android 横屏触屏；其他平台与正式首发平台待验证。  
**引擎**：Godot 4 + GDScript。  
**关键词**：温暖、创造、发现、陪伴、低压力、可见变化。

### 一句话介绍

玩家来到一座逐渐安静的小岛，帮助兔子、狐狸、乌龟和岛上的小动物，修复道路、照料花园、收集有趣的物品、装饰家园，让小岛一点点重新热闹起来。

### 游戏想带给孩子的感受

- **我能做到**：简单操作即可得到正向反馈，不需要快速反应。
- **这里因我而改变**：桥修好了、花长出来了、动物回家了、庆祝彩旗挂起来了。
- **我可以自己选择**：主线引导清楚，但完成基础教学后可自由探索和装饰。
- **每次回来都有熟悉的世界**：进度和摆放保留，没有签到压力或惩罚。
- **动物是伙伴，不是工具**：动物有性格、动作、请求与感谢，但不引入复杂数值养成。

## 02. 世界观与故事总线

**【已定方向】**小岛曾是热闹的自然乐园，旧桥损坏、花园荒废、动物搬离后逐渐安静。玩家作为新来的小小建设者，通过帮助动物让岛屿恢复生机。没有敌人、死亡或失败结局。

**【新增建议】故事分为四幕：**

1. **初来小岛：重新连起来**——帮助兔子修桥，找到种子，重新走到池塘边。
2. **伙伴回家：让岛屿有生气**——帮助狐狸修小屋、乌龟整理花园，探索秘密角落。
3. **大家一起建设：让小岛变漂亮**——铺小路、搭鸟屋、收集植物、整理额外地块。
4. **小岛庆祝日：一个温暖的阶段结尾**——和三位主要伙伴互动，庆祝第一阶段的改变；庆祝后仍可自由玩。

**后续扩展叙事【新增建议】**：不是反复出现“岛屿又坏了”的危机，而是以季节、自然观察、动物小故事、节庆准备和新景观为主题，持续丰富同一座岛。

## 03. 核心玩法与长期循环

### 3.1 单次 3—8 分钟的轻循环【新增建议时长，需试玩验证】

发现动物或环境线索 → 接受一个简短目标 → 走动探索 / 点击 / 收集 / 拖拽 → 获得即时反馈 → 世界出现可见变化 → 继续探索或装饰。

### 3.2 五条玩法主线

| 玩法系统 | 玩家做什么 | 典型反馈 | 首版 / 长期定位 |
|---|---|---|---|
| 探索发现 | 在已开放区域寻找物品和隐藏角落 | 发现图鉴、装饰或小故事 | 首版基础；后续扩展 |
| 动物伙伴 | 与兔、狐、龟互动，帮助解决小问题 | 新动作、感谢、环境变化 | 首版核心；后续丰富个性 |
| 轻任务 | 收集、配对、照料、交付、简单建造 | 任务完成、世界变化 | 首版 12 任务；后续任务包 |
| 建造装饰 | 固定关键建造点 + 指定地块内自由摆放 | 亲手改变小岛样子 | 首版基础；后续扩充家具与地块 |
| 收藏与观察 | 收集种子、贝壳、自然发现物 | 图鉴页面、外观变化 | 首版萌芽；后续可选深化 |

### 3.3 明确不做的系统【已定方向】

不做战斗、死亡、体力惩罚、复杂经济、随机抽奖、强制签到、广告、内购、陌生人社交、多人联机、排行榜、开放 UGC、程序化大世界。离线优先，不要求账号登录。

## 04. 地图与场景规划

### 4.1 首版地图【已定方向】

一张可探索小岛，包含初始活动区、桥另一侧、池塘/花园等功能景观；以桥、动物住所、花园作为关键建造点，至少一个区域随任务开放。具体分区数量与最终美术布局以场景设计为准。

### 4.2 后续场景层次【新增建议】

- **中心草地与小广场**：主入口、兔子、庆祝装饰和任务引导。
- **河流与木桥**：最早的建设成就，承担通路开放。
- **狐狸小屋与林边**：探索和隐藏发现主题。
- **池塘与乌龟花园**：植物、浇水、观察自然。
- **整理地块与装饰庭院**：玩家自主摆放的展示空间。
- **季节景观角**：在后续版本通过同一地图的外观变化增加新鲜感，避免过早扩建第二张大地图。

**地图扩展原则**：先优化一张地图的视觉密度、通行、目标可读性和交互，再考虑第二个场景；新区域必须带来新玩法，不只增加行走距离。

## 05. 角色体系

### 5.1 三位主要伙伴【已定方向】

| 伙伴 | 性格/职责 | 基础玩法 | 后续成长空间【建议】 |
|---|---|---|---|
| 兔子 | 热情、负责新手引导，喜欢种子 | 修桥、种植、指引 | 送小礼物、一起布置小广场 |
| 狐狸 | 好奇、擅长发现隐藏物品 | 建小屋、探索、找线索 | 藏宝路线、发现故事 |
| 乌龟 | 温和、耐心，喜欢池塘与花园 | 浇水、拼放、照料 | 植物观察、园艺小任务 |

### 5.2 动物表现规范

首版至少提供 idle、happy、interact、request 的表达，可先用 2—3 个基础动作与表情替代复杂骨骼动画。对话保持简短，重要提示可重复查看。

### 5.3 其他动物

Q009 的小鸟定位为**环境互动角色**，不默认成为第四位主要伙伴。未来可增加蝴蝶、鱼、小鸟等环境生物，但应以低成本视觉与观察玩法为主，不增加复杂养成负担。

## 06. 任务体系

### 6.1 任务设计规范【已定方向】

任务类型：寻物、配对/拼放、照料、交付、建造。状态：locked、available、in_progress、completed；如无需单独领奖，不引入多余领取步骤。每个核心任务至少改变一项世界状态。

### 6.2 首版 12 个任务【GDD 草案；实现细节以代码为准】

| ID | 名称 | 主玩法 | 世界变化 / 成果 |
|---|---|---|---|
| Q001 | 修好小桥 | 找木板、拖拽修桥 | 桥可通行 |
| Q002 | 兔子的种子 | 寻找种子、种植 | 幼苗出现 |
| Q003 | 池塘边的石头 | 石块拼放 | 池塘互动开放 |
| Q004 | 狐狸的小屋 | 收集材料、交付 | 狐狸入住 |
| Q005 | 乌龟的花园 | 浇水、植物摆放 | 花园生长 |
| Q006 | 花园装饰 | 放置装饰 | 获得新装饰 |
| Q007 | 隐藏的贝壳 | 探索发现 | 贝壳装饰 |
| Q008 | 小路连起来 | 铺设路面 | 新路径视觉变化 |
| Q009 | 鸟屋计划 | 收集材料 | 小鸟互动开放 |
| Q010 | 种子收藏 | 寻找三种种子 | 植物外观解锁 |
| Q011 | 帮忙整理 | 摆放三件物品 | 额外整理地块视觉开放 |
| Q012 | 小岛庆祝日 | 和兔、狐、龟分别互动 | 永久庆祝视觉、阶段结尾 |

> GDD 明确称这些任务为**内容草案**，数量、坐标和具体前置条件需关卡制作时校验。Q001—Q011 据近期开发报告已实现并通过回归；Q012 在最近讨论中已确定实施方案，但本文件**不声称 Q012 已经完成**。

### 6.3 后续任务包设计【新增建议】

不无限增加“收集三个东西”的重复任务。每个新版本的任务包至少引入一种新的**表现或选择**，但保持操作简单。

- **园艺任务包**：照料不同植物、观察成长阶段、布置花圃。
- **森林发现任务包**：跟随狐狸线索，寻找隐藏的自然物。
- **伙伴友谊任务包**：给动物准备小角落、一起庆祝小成就。
- **装饰挑战任务包**：按图示完成一个布置，再允许自由改摆。
- **季节观察任务包**：发现春花、夏蝉、秋叶、冬日景观（不绑定真实日历或签到）。

## 07. 建造、装饰与收集

### 7.1 建造层级

- **关键建造**：桥、小屋、花园等固定建造点；不能任意移动。
- **装饰建造**：限定地块内拖拽摆放；有合法/非法预览；支持移动、移除与恢复。
- **场景变化**：修复、植物成长、庆祝装饰等由任务状态驱动。

### 7.2 装饰目录【新增建议】

首版目标约 15 件装饰，不代表当前已全部实现。建议分类：庭院（栅栏、花盆、路灯）、自然（花丛、石头、小树）、纪念（贝壳、小风车、庆祝牌）、生活（木箱、竹篮、小凳）。先核对实际可放置件数与“仅作为任务物件”的区别。

### 7.3 收藏与图鉴【新增建议，后续版本】

可建立非竞争性的“发现册”：植物、贝壳、自然景观、动物故事。仅记录已发现与未发现，不设置稀有度付费、重复抽取或限时惩罚。每个条目配图和一句简短介绍。

### 7.4 资源规则【已定方向】

木板、种子、石块和装饰物足够支撑首版。装饰星星可以作为非付费进度反馈，但不形成多货币、合成链、耐久度或资源损耗系统。

## 08. 操作、UI 与儿童体验

### 8.1 触屏操作

Android 横屏优先验证：大尺寸互动按钮、虚拟摇杆或直观移动方式、拖拽放置、可视化高亮、宽容命中区域。鼠标键盘用于开发验证，不应替代触屏体验验收。

### 8.2 信息架构【新增建议】

主菜单 → 继续游戏 / 开始游戏 / 设置 / 家长信息；游戏内 → 当前任务提示、互动按钮、装饰入口、发现册、设置。避免多层菜单和过多常驻图标。

### 8.3 引导与无障碍

- 首次 3—5 分钟体验“探索—行动—世界变化”的闭环（设计目标，需实测）。
- 提示短句 + 图标 + 目标轻高亮；长时间未操作可提供可关闭的温和提示。
- 不能要求精确拖拽或快速反应；错误放置可以无限重试。
- 尽量减少必须阅读的文字；音效不能成为唯一反馈渠道。
- 色彩、轮廓、目标尺寸适合儿童；不依赖单一颜色区分成功失败。

## 09. 画面、动画与声音

**【已定方向】**温暖的 2D 卡通自然小岛，低复杂度、柔和色彩、清晰轮廓。角色需要待机、开心、互动、请求反馈。音效柔和，错误操作不使用刺耳提示。

**【新增建议】美术制作分三层**：

1. **功能灰盒**：确认可读性、操作和地图布局。
2. **统一风格美术替换**：统一地形、建筑、动物、植物、装饰的比例、光影和色彩。
3. **细节表现**：环境粒子、花草摆动、庆祝动画、轻量镜头反馈与环境声。

美术风格与资源授权需要单独立项，不把占位绘制视为最终美术验收。

## 10. 存档、技术架构与内容生产

### 10.1 存档

保存任务、解锁区域、已收集物品、装饰摆放、植物状态与必要设置；退出重进恢复；版本迁移；损坏存档安全处理；不保存儿童身份信息。测试使用隔离存档，不得触碰正式存档。

### 10.2 架构演进【新增建议】

当前原型按任务逐步增加状态 API 和 `main.gd` 分支，适合快速验证，但长期任务扩展应逐步转向**配置驱动的任务定义、独立交互对象与通用奖励/世界变化接口**。这与 GDD 的“任务系统应配置化”一致。

注意：**不在 Q012 完成前启动全面重构**。先冻结 MVP 可玩版本、补足自动化和试玩证据，再按模块渐进迁移，确保每一步可回归。

### 10.3 内容生产模板【新增建议】

每个新增任务都填写：任务 ID、目标年龄、前置条件、目标区域、物品 ID、操作、失败保护、世界变化、奖励、存档字段、交互优先级、自动化测试、触屏验收。

## 12. 各版本必须回答的验收问题

- **玩法**：孩子是否知道下一步做什么？错误操作能否重试？完成后是否看得见变化？
- **体验**：能否在目标设备上顺利触摸、移动、拖拽？是否有难以点击的目标？
- **自由度**：主线完成后是否还能探索、摆放、互动，而非只有“游戏结束”？
- **内容**：是否出现大量同质的“收集三个物品”任务？每个新版本是否有真正新鲜的体验？
- **存档**：异常退出、升级和重进是否保留进度？重复互动是否重复发奖？
- **质量**：自动化回归、实际设备、视觉检查分别有证据；不能相互替代。
- **安全**：离线核心玩法、无广告内购与陌生人社交、不收集不必要的儿童信息。

## 13. 产品风险与优先级

| 风险 | 当前表现 | 建议优先级 |
|---|---|---|
| 任务完成但不好玩 | 任务通过自动化，不等于儿童能理解 | 极高：V0.9 试玩验证 |
| 地图只是占位绘制 | 功能完整，但难体现温暖的儿童世界 | 高：V0.6 美术统一 |
| 装饰自由度不足 | 任务物品不等于可移动、可移除的装饰 | 高：V0.5 补齐 |
| 任务实现高度定制 | 继续新增任务可能造成 `main.gd` 和状态文件膨胀 | 中高：V0.4 渐进整理 |
| Android 实机体验未知 | 桌面和自动化通过不等于触屏通过 | 高：V0.7 必须实测 |
| 过早扩地图与系统 | 扩大制作成本，延迟发布验证 | 严格控制：V2.0 才评估 |

## 14. 当前需要决策的事项（不阻断 Q012）

1. **V1.0 的发布平台**：Android 优先验证已定，正式首发平台、渠道和屏幕适配标准待实测。
2. **V1.0 的装饰深度**：明确约 15 件装饰中多少可自由移动、旋转、移除；不能把任务摆件全部算作自由装饰。
3. **V1.0 的美术标准**：确定统一的 2D 卡通参考风格、角色比例、地形与 UI 规范。
4. **V1.0 的发行方式**：定价与商业模式仍待验证；首版不引入广告、内购或诱导消费。
5. **V1.x 内容更新频率**：先由试玩反馈和制作成本决定，不设强制周更或签到活动。
